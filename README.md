# Kyle Ferguson — Portfolio

A lightweight, responsive portfolio for `https://kyleferguson91.github.io/Portfolio/`.

## Content focus

This is a personal portfolio with a name-led introduction, selected project write-ups, work experience, education, and skills. It presents Kyle's own contributions without service packages or sales copy. Stricklands work is described generally; private source, raw internal screenshots, customer information, locations, and system details are excluded. Only reviewed, sanitized interface captures are published. Programming projects link to their public GitHub repositories.

## Files

- `index.html` — accessible single-page portfolio
- `styles.css` — responsive styling with a desktop profile sidebar; no framework or build step
- `script.js` — progressive enhancement for the active section indicator
- `favicon.svg` — simple text favicon
- `toolbox-overview.jpg`, `toolbox-review.jpg` — sanitized captures of the optional companion toolbox interface, not the standalone Windows executable; no selected computer or internal workspace information

All navigation and the screenshot disclosure work without JavaScript. Screenshots document the interface; they do not imply that operational tools were run during the portfolio work.

## Design references

The layout was informed by Brittany Chiang's persistent identity and reading navigation (https://brittanychiang.com/), Lee Robinson's concise personal writing (https://leerob.com/), and Lynn Fisher's emphasis on individual identity (https://lynnandtonic.com/). The code, copy, colours, and assets are specific to Kyle's portfolio; no reference-site code or assets were imported.

## Project selection

Sanitized projects cover the standalone Windows IT Toolbox, PC user migration, a workflow workspace, the read-only operations console, employee training videos, and everyday business trackers. Keep the workspace entry explicitly in progress; its repository documents service/device acceptance still outstanding. Internal summaries omit repository links, training URLs, and operational configuration. Training descriptions do not imply that every draft lesson is published.

Lead with transferable IT support and software strengths; the current employer belongs in Experience. Separate customer-facing work history from Computer Programming education. Languages describe education/project experience rather than daily professional use. Keep AI to one brief development-method mention. Education can later expand to include earned certifications; do not publish placeholders or unearned credentials.

Featured programming projects cover Java/Spring Boot microservices and BBC News Reader. Descriptions were checked against repository documentation or the relevant application routes/controllers. Basic exercises, empty repositories, and duplicate implementations are not featured.

The GitHub Pages project site is served from the `Portfolio` repository's default branch. Keep the canonical URL and LinkedIn destination aligned if the project is moved.
